How SFT learns only the answer

The model reads every token of the chat. Only the answer gets a loss. The gradient then flows back into the prompt, so the model learns to use the question, but it is never trained to write it.

Every number below is measured, on 8 Oct 2026. Model: a tiny model built like ours (4 layers, tied embedding table with 50,304 rows, RMSNorm, causal attention, SwiGLU), fp64 on CPU. The chat was tokenized by our own prepare_sft_data.py (template tulu-plain-v1).

prompt: label 65535, ignored trained: answer tokens and the end token padding: label 65535, ignored

The answer in four steps

  1. Forward: all 28 positions are computed, the prompt and the padding too.
  2. Loss: only the 3 trained positions are scored. The other 25 add exactly 0, and N = 3.
  3. Backward: the gradient starts on those 3 rows only. In every layer below the top, it reaches the prompt positions through attention, because the answer read them.
  4. Padding gets exactly 0 everywhere. It comes after the answer, and attention only looks back, so nothing ever reads it.

1The row the model gets

One chat: the user asks “What is the capital of France?” and the answer is “Paris.” It becomes 24 tokens. The input is the tokens without the last one. The label at each position is the next token, or 65535 where we don't want a loss.

2Forward: every position is computed, three are scored

The forward pass is the same as in pretraining. Every position gets 50,304 scores (the logits) and a probability for every token. The label decides which positions count.

loss = (10.984 + 10.850 + 10.946) ÷ N = 10.927    with N = 3 trained tokens (not 28, not 23)

3Backward starts at the logits, on three rows only

The gradient of the loss with respect to the logits is a 28 × 50,304 table. For a trained row it is (p − 1) ÷ N on the right token and p ÷ N on every other token. For an ignored row the kernel writes zeros.

So the loss never pushes a prompt position to predict its next prompt token. That is the masking.

4Into the layers: the prompt gets gradient through attention

Here is the part that is easy to miss. In layer 4, the answer position ↵ builds its output by reading the keys and values of every earlier position, the prompt included. The backward pass runs along the same reads in reverse. So the prompt positions get gradient one layer down, even though their own prediction is never scored.

5Which weights learn from which positions

Each weight matrix is shared by all positions, so its gradient is a sum over positions. The table counts the positions that add something to that sum.

The embedding table is used twice (it is tied): once to look up the input tokens, once as the output layer.

The two parts add up to PyTorch's own gradient exactly (largest difference 0.0).

7Sixty training steps: what actually gets learned

I trained the same model on this one chat for 60 steps (AdamW, LR 3e-3) twice: once with our SFT labels, once with every position trained, as in pretraining. After each step I measured how well it predicts the true next token at every position.

With our labels the answer is learned almost perfectly, while the prompt stays near 9. But it did drop from 10.8 to 9.0 without being trained, so I checked what that drop is. At the prompt positions after 60 SFT steps, −log p of:

token−log pmeaning
the true next prompt token9.00the same: the model does not know which prompt token comes next
any other token of this chat9.08
tokens that never appear in the chat15.55pushed down from 10.8 by every step
the answer tokens (Paris . eot)2.11the model now wants to say the answer everywhere

So the drop is not learning the prompt. The ~50,000 tokens that never appear were pushed far down. That makes all 17 tokens of this chat look a bit more likely, all by about the same amount (the true next token ranks about 9th of 50,304, inside that group). On a real run with thousands of chats, this kind of drift in what the model says by default is what the before-and-after tests on MMLU and HellaSwag are meant to catch.
