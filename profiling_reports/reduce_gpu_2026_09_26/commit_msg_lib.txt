reduce: fix GPU/CPU reduction bugs (mean crash, wrong axes, int mean, race)

Measured on 1x H200 with a 43-case test (GPU and CPU against an exact double
reference, one process per case). Before: GPU 9 ok / 13 wrong / 11 crashed of
the first 33 cases; CPU wrong on all 6 middle-axis cases. After: 43/43 on both,
compute-sanitizer memcheck 0 errors, racecheck 0 hazards (was 11,521).

1. Mean crash (bf16/fp16/integer input): dispatch_mean_gpu sized the config and
   shared memory with the input type instead of the accumulator (arg_t), so the
   kernel wrote past its shared memory. Now arg_t, as the other dispatchers and
   PyTorch do (ReduceConfig(sizeof(arg_t))).
2. Wrong last-axis results: block_x_reduce treated the 2-D block as 1-D (rows
   overwrote each other in shared memory, shuffles crossed rows). Now the same
   algorithm as PyTorch's block_x_reduce.
3. Integer mean returned 0: the 1/n factor was stored in the int64 accumulator
   type, which is 0 for n >= 2. Now double; the sum stays exact in int64. The
   integer mean now returns Float64 like the CPU mean and NumPy (was Float32);
   GPU and CPU results are bit-identical.
4. Middle-axis reduction (outer > 1), GPU: only the first slab was computed.
   Now num_outputs = outer * inner and the kernel maps each output to its slab.
5. Generic path (non-consecutive axes, non-contiguous input), GPU: launched with
   empty offset calculators. setup_generic_path now builds them (and refuses
   more than 10 dims per side instead of computing wrongly).
6. Middle-axis reduction, CPU: the OuterContiguous consumers assumed outer == 1.
   Now demoted to the Generic carry-add path at all 6 CPU layout sites.
7. Multi-CTA combine: __syncthreads() between block_y_reduce and block_x_reduce
   (unsynchronised shared write/read on the same slots).

Fixes 2, 4, 5 and 6 follow the June 2026 fixes in
master_gau_latest_sm_86_RTX_3060,
which never reached this repo. Not covered by the test: argmax/argmin and
variance over a middle axis (same remap/demote, not measured). Speed not
measured; the changes add one integer division per thread, one barrier per
multi-CTA tile, and 4 more output bytes per integer-mean output.
