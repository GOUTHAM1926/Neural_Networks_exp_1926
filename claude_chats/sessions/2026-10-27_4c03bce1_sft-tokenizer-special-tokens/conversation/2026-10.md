## 2. Keep it or add special tokens? Keep it for now.

On 10-15 the doc (§45.6) recommended moving to special ids 50257/50258/50259, but only after a test of plain text (A) against special ids (B). That test was never run, and the full run was then done on A. My advice now is to keep A for this model:

- **No published result says special ids score better.** Tülu 3 is a strong recipe and uses plain-text markers, the same as you.
- **Switching costs a lot:** a new SFT run, 3 new embedding rows to start and train, and changes to DPO data, eval and the HF export.
- **What special ids actually give you:** a user cannot fake a role marker by typing `<|assistant|>`, each chat is about 20 tokens shorter (~1.6%), and parsing roles and stops is cleaner. These matter for a product chatbot, not for benchmark scores.

When to add them:
- **Next base model:** reserve the ids in the tokenizer from the start, keep them out of pretraining data, and train them in SFT.
- **If the DPO team insists on special ids:** run SFT again with them first.

⚠️ **One real risk:** the DPO script on your laptop ([prepare_dpo_data_tokenize.py:57-69](prepare_dpo_data_tokenize.py#L57-L69), dated 10-15) still maps the markers to 50257/50258/50259. Your checkpoint has never seen those ids as inputs. Check that the DPO team switched to plain text as your README says. If they did not, their data will not match your model.

## 3. Has anyone published on this?

Nobody has published a clean test of "same markers, special id vs plain text" in SFT. The doc found none on 10-15, and my searches today found none either. The closest published results:

| Source | What it found |
| --- | --- |
| **Tülu 3 paper**, Table 13 | 5 chat templates, same SFT setup. The plain-text ones scored 52.6–53.0. The Llama 3 template is the only one with special-id role markers, and it scored lowest at 51.6. This doesn't isolate the question: the layout differs too, and in the Llama 3 base model those ids' embedding rows are zero. |
| **OLMo 3 paper** | Putting chat special tokens into midtraining data made the model print them, and GSM8K fell from 49.43 to 0. The same layout as plain text kept 46.02. Their advice: "Leave special tokens for SFT stage". |
| **Laguna M.1/XS.2 report**, §4.1.1 (I read the PDF today) | They added special chat tokens with random embeddings. The small model was fine; the bigger one got gradient spikes, dead experts and unstable training. Their fix: start each new token at the mean of its sub-token pieces (e.g. `<think>` = mean of `<th`, `ink`, `>`), then train 100 steps with everything frozen except the embeddings and LM head. |
| **Llama 3 base** (imone model card) | The special-token rows are zero in the base model, which can cause NaN gradients. |

If you ever switch to special ids, the Laguna fix applies to your model directly. Start `<|assistant|>` as the mean of the rows for `<`, `|`, `ass`, `istant`, `|`, `>`. Do not start it from the current row 50258: your input and output embeddings share one table, so pretraining only ever pushed that row down as an output.
