2. Key Technical Concepts:

- **Hopper thread-block clusters (CGA)**: `barrier.cluster.arrive/wait`, `mapa` (cross-CTA smem address), `%cluster_ctarank`, TMA multicast, `cudaLaunchAttributeClusterDimension`.
- **TMA multicast** (`cp.async.bulk.tensor.4d...multicast::cluster`): completion (`complete_tx`) fires on the same-offset mbarrier in EVERY masked CTA (not issuer-only).
- **Partitioned multicast (the permanent fix)**: each CTA loads its own 1/N slice of the shared operand (CUTLASS truncates TMA box by num_multicast along the outer dim, `copy_traits_sm90_tma.hpp:996-1002`) and multicasts it. SYMMETRIC work → CTAs stay in lockstep → race-free by construction. 1× DRAM. A→row-slice BM/CLUSTER_N; B→col-slice BN/CLUSTER_M.
- **Leader-only multicast (RACY, now superseded)**: one CTA issues full-A → non-leader depends on cross-CTA delivery → asymmetric → drift → mbarrier PHASE corruption at large-K+persistent scale → flaky crash.
- **Race/Heisenbug signature**: crashes bare, vanishes under memcheck/synccheck/racecheck (all 0 errors) → timing race, not memory/logic/barrier-API bug.
- **bz = beta-zero** (proven by experiment): kernel that skips reading C; counterpart `badd` = beta-add (reads+adds C). Epilogue token family: `bz/badd/bias`.
- **Raw-load + software-transpose workaround**: NN's B and TN's A/B are MN-major in memory but wgmma needs K-major smem, so loaded raw (unswizzled) via `init_4d_tma_raw_KX_sm90` then `transpose_to_kmajor_swizzled`. This is OUR workaround; CUTLASS uses native MN-major TMA. It's the documented NN/TN perf bottleneck (~11-23% of cuBLAS).
- **Native MN-major TMA descriptor (§H11.4, unsolved)**: the future-proof way to eliminate the raw-transpose. Requires proving the `CUtensorMap` box-dim/global-stride that makes TMA land data in the exact swizzle pattern `ss_smem_selector<Major::MN,...>` expects.
- **Makefile header-dep gotcha**: `-include *.d` present but no `-MMD -MP` to generate them → `.cuh` edits never trigger rebuild → stale binaries. Fixed by adding `-MMD -MP` to CPPFLAGS.
- **Persistent kernel + mega-tile scheduling**: `mega_grid_m=ceil(grid_m/CLUSTER_M)`, `block_row=mega_row*CLUSTER_M+cluster_local_m`, `block_col=mega_col*CLUSTER_N+cluster_local_n`; `cluster_local_m=rank%CLUSTER_M`, `cluster_local_n=rank/CLUSTER_M`.
- **EMPTY barrier count** = `NUM_CONSUMER_WARPGROUPS × (SHARE_M + SHARE_N − 1)` (CUTLASS's row∪col formula), where SHARE_N=NEEDS_A_MULTICAST?CLUSTER_N:1, SHARE_M=NEEDS_B_MULTICAST?CLUSTER_M:1.
