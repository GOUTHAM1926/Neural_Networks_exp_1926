Extraction logic (final, fixed version):
       ```bash
       MATCHES=$(awk -v pat="$PATTERN" '
         /^[ \t]*Function : /  {
           match_this = ($0 ~ pat)
           if (match_this) { printing=1; count++ } else { printing=0 }
         }
         printing { print > "'"$OUT"'" }
         END { print count+0 }
       ' "$CACHED_DUMP")
       ```
       This single-pass, awk-internal counting design was adopted specifically because a two-step design (awk writes `$OUT`, then a SEPARATE `grep -c` re-reads `$OUT` to count matches) was tested and intermittently reported 0 matches even when `$OUT` demonstrably had correct content (reproduced 100% of the time in that specific test sequence, root cause never fully pinned down — looked like a same-file read-after-write timing/consistency quirk, not a pattern-matching bug).      - Real bug #3 (fixed): intermittent `MATCHES=0` false-negative from the two-step grep-re-read design — fixed via the single-pass awk-internal counting redesign above.
