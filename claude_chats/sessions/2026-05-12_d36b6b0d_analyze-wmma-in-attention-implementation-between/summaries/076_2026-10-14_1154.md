2. Key Technical Concepts:

**Kernels.**
- Vj2 (new FA3-style backward, opt-in `USE_VJ2=1`, dense causal only):
  - 128 keys per block, 384 threads;
  - loader warpgroup (warp 0 does TMA, warp 1 is the dQ writer);
  - 2 compute warpgroups;
  - setmaxnreg 24/240.
- Vj1d: the default; deterministic dK/dV; has packed A/B.
- Vj1: `USE_FLASH=1`, atomic dK/dV.
- v44: `USE_DETERMINISTIC_DQ=1`.
- v62: the forward, persistent with 132 CTAs; template MODE 0 = dense, 1 = B, 2 = A.
- Naming: "v2" = the SFT packing plan; "Vj2" = a kernel name.

**GPU and hardware concepts.**
- wgmma / HGMMA: SS vs RS (A from registers); m64n64k16 vs m64n128k16.
- Descriptors: SW128; LBO = stride between 64-element N blocks for MN-major (CUTLASS `Major::MN` B128: `((T,8,m),(8,k)):((1,T,LBO),(8T,SBO))`); `desc_add`.
- Uniform vs normal registers; R2UR copies.
- Shared-memory bank conflicts (wavefronts).
- TMA 2-D reduce vs 1-D bulk reduce (`cp.reduce.async.bulk.global.shared::cta.bulk_group.add.f32`).
- FA3 schemes: fragment-order dQ accumulator (`R2STiledCopydQaccum`); SingleTileBwdLPTScheduler (heaviest first, 8 heads per L2 section = 40 MB / 4 MB per head).
- Named barriers.
- Stall reasons: short_scoreboard, mio_throttle, long_scoreboard, barrier, wait, warpgroup_arrive. warpgroup_arrive = the 4 warps of a warpgroup waiting for each other at a wgmma group start; it is NOT exported as a per-line column in the ncu source CSV, so it equals the "unexplained" samples.
- LSE = log-sum-exp per query row (pre-multiplied by log2e); exp(x) = e^x; the GPU's ex2 computes 2^x.

**Measurement methods.**
- Same-session A/B with box library snapshots via `LD_LIBRARY_PATH` (tva_vj2 has RUNPATH).
- 6-round alternation with paired t for small effects.
- ncu `--set full` with `--import-source`; `-lineinfo` build (SASS identical).
- nsys `--trace=cuda` breakdown (kernels + memsets + trace).
- ncu unit traps: DRAM Mbyte/Gbyte, time us/ms.
- FA3's Python API adds about 0.1 ms per call, so kernel-level comparison is the honest one.
