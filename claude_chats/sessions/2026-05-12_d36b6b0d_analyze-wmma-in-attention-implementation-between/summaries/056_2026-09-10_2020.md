## 2. Key Technical Concepts

- **Two dispatchers:** ours = tier-1 exact (M,N,K) table (457 rows, `kTable_nn/nt/tn`) + tier-2 fitted tree (`tree_nn/nt/tn`); Kota's = `Bgemm_sm90_dispatcher_kota.cu` (2,079 lines, verbatim, `_kota`-suffixed exports). **The hybrid = our kernels + HIS selection logic.**
- `BLUBLAS_KOTA_DISPATCH=1` — the runtime flag that selected Kota's dispatcher (now **removed**, his path is unconditional)
- `BLUBLAS_HAS_SM90` — from `ARCH_DEFINES`; without it the SM90 block is preprocessed out and every BF16 GEMM takes the SM89 legacy path (−37%)
- `BLU_MAX_STEPS=N` → `warmup=N/10`, `stable=N/2`; changes LR regime → different data → different switching power
- `BLU_ZERO_V2=1` (SymmetricShardedOptimizer, PER_BUCKET) / `BLU_SYMMETRIC=1` (NCCL symmetric memory, NVLS); both default 0
- `Sm90RuntimeSel` lives in the kernel template header, not either dispatcher — survives the dispatcher swap
- Kernel discriminator: `blublas_ws::bgemm_sm90_kernel<Sm90WarpspecConfig<...>>` = ours; `nvjet_*` = cuBLAS
- **Persistent kernels:** grid is `132x1x1` (SM count) regardless of shape — grid does NOT encode M,N
- H200: 60 MB L2, 228 KB smem/SM, 65,536 regs/SM, 132 SMs, 700 W factory cap, 1980 MHz max
- Shape formula: M = B·T for nn/nt; K = B·T for tn; `global_batch` only sets `GRAD_ACCUM`
- SM_ARCH=**90** (not 90a) — Makefile maps 90 → `-gencode arch=compute_90a,code=sm_90a`
- Makefile hierarchy: top `blutrain_ours/Makefile` (orchestrator, WITH_BLUBLAS), `Tensor-Implementations/Makefile` (builds BOTH libtensor and libblublas, holds `BLAS_CPPFLAGS`), `BluBridge-BLAS/Makefile` (**never invoked** by the trainer)
- `WITH_BLUBLAS=1` adds `-DWITH_MYBLAS` at **compile** time (GenMatmul.cu is entirely inside that guard) plus `-lblublas` at link; `BLAS_STAMP` forces recompile on backend switch
