2. Key Technical Concepts:

**Kernels.**
- Vj1d: 64-key blocks, one warpgroup of 128 threads, 2 CTAs/SM; dQ via fp32 TMA reduce-add; dK/dV one-writer bf16 partials plus a fixed-order greduce (deterministic).
- Vj2: FA3 layout.
  - 128 keys per block; 384 threads.
  - Loader warpgroup: warp 0 does the TMA loads (K/V once; Q/dO plus LSE·log2e and D by 1D bulk copy, 2 stages); warp 1 is the dQ writer.
  - 2 compute warpgroups of 64 keys each; setmaxnreg 24/240.
  - Swapped score GEMMs Sᵀ = K·Qᵀ; P and dS in registers for the RS wgmma of dV and dK.
  - dS computed from fp32 P.
  - dQ via smem staging plus named-barrier handoff to the writer.
  - Named barriers: 1 = both groups (256), 2/3 = dQ_full (160), 4/5 = dQ_empty (160), 6/7 = epilogue (128).
  - Dense only, S%128==0; otherwise routed to Vj1d.

**Research facts (ncu).**
- Vj1d 3.626 ms vs FA3 2.494 ms, with the same tensor busy time (1.66 vs 1.74 ms).
- L2 reads 81.0M vs 40.9M (1.98×, matching 299,520 vs 152,064 q-tile visits).
- Stall shares: ~14% at the dQ barrier/fence, ~10% GEMM waits, ~7% P/dS round trip.
- Precision emulation: dS from fp32 P cuts RMS error 17–30% (normal inputs).

**Vj2 v1 results.**
- Correctness: 605/605; dK/dV bitwise.
- Precision vs Vj1d (worst ratio per check): dQ lower in 57/84 (median 0.91), dK lower in 61/84; the known G6 D10 case went 1.156 → 0.891.
- Speed: −5.2 to −13.0% vs Vj1d (mean −10.6%); vs FA3 1.20–1.28×; vs cuDNN 0.95–1.11× (faster only on 2 small shapes); vs FA3 deterministic 0.96–1.05×.
- Gate ≥10% met on 9/13.
- nsys kernel: 3197 µs vs Vj1d 3615 µs vs FA3 2495 µs (the FA3 number is from 10-12, cross-session).
- ncu: 1,096M instructions vs FA3 625M; L2 reads 42.7M (≈FA3); generic `LD.E/ST.E` caused lg_throttle; descriptors rebuilt 5.4 instructions per HGMMA (23%).

**Fix (Vj2 v2, md5 bbd977be).**
- The shared base is rounded by pointer arithmetic.
- `desc_add` (constant 32-bit add) from base descriptors made once.
- SASS 2520→1816 lines; LD.E/ST.E 161→0; LDS/STS 0→96; 0 spills.

**SFT facts.**
- Template `tulu-plain-v1` (plain-text markers, 6–7 tokens each).
- EOS / pad id 50256 (GPT-2's only special token).
- Label ignore value 65535: uint16, not a token.
- Labels: `lab = where(mask[1:], ids[1:], 65535)`; inputs = `ids[:-1]` plus pad 50256. The 50256 after the answer in inputs is padding; END is only a label (at the last answer token).
- Loss kernel: counts valid labels (denominator, global per step), the forward skips the softmax for ignored rows, the backward zeroes the gradient rows.
- Megatron uses a 0/1 loss_mask multiply; PyTorch/HF/TRL/torchtitan/Liger use ignore index -100.
- Padding id doesn't matter: proven with bit-identical gradients, because of right padding, causal attention and 65535 labels.
- Answer gradients update prompt-token weights through attention; SFT doesn't teach predicting the prompt (20-seed test).

**Head-dim-64 bug.**
- Causal hd64 on H100/H200 goes to the non-causal `gqa_v2` forward and `launch_gqa_backward` (no mask).
- Reachable via the `bluscript.cpp:73` default `head_dim=64`.
- Production yaml uses 128.
