2. Key Technical Concepts:

**Hopper TMA**
- 2D stacked vs 3D (batch-axis) tensor-map descriptors.
- Out-of-bounds rows are dropped on stores and zero-filled on loads.
- `cuTensorMapEncodeTiled`; `cp.async.bulk.tensor.3d.global.shared::cta.bulk_group`.

**Async-copy pipelines**
- `cp.async` commit/wait group semantics; the prologue must commit STAGES-1 groups (CUTLASS `mma_multistage.h` uses `clear_mask` + `cp_async_fence`).

**Alignment routing (CUTLASS `can_implement`, kErrorMisalignedOperand)**
- 16-byte vector loads.
- Contiguous-extent alignment.
- A generic align-1 fallback kernel.

**Split-K**
- atomicAdd onto C, which is nondeterministic run to run.
- Beta must be applied exactly once (CUTLASS `reduce_split_k.h`).

**Barriers**
- `__syncthreads` in conditional code is undefined unless the condition is uniform across the block.
- Block-uniform early returns are fine; per-thread ones before a barrier are not.

**Other kernel details**
- XOR swizzle must stay inside the tile row width.
- The fp32 SM89 template assumes BK=16; enforced with a `static_assert`.

**Verification methods**
- SASS fingerprinting: cuobjdump, md5 per kernel, addresses stripped, whitespace normalized.
- The test framework uses a componentwise GEMM error bound `4*S*(e_acc+u_out)`, a NaN-prefilled C for beta=0, a padding-untouched check, and per-case FNV checksums for bit-for-bit old/new comparison.
- One process per (type, op, shape) group, so a crash only loses its group.

**GPU and box practice**
- GPU lock: `nvidia-smi -c EXCLUSIVE_PROCESS` (root on the 2x box). It also refuses our own second process, so never run two of ours on one GPU. Restore DEFAULT via an EXIT trap.
- Architecture dispatch: H200 sm_90 uses SM90 kernels; Ada sm_89 and the 3060 sm_86 run all bf16/fp16 through the SM8x kernels; fp32 uses the SM89 path for sm ≥ 89 and the SM86 path for sm < 89.
- `git apply --cached` gives an index-only two-commit split.
