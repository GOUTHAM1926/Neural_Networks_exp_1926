2. Key Technical Concepts:

**HAS_POS (RoPE positions switch)**
- Compile-time template flag; the launcher picks it with `positions == nullptr`.
- The pretraining instantiation is SASS-identical: 9/9 Kruthik kernels, 13/13 for fp32 earlier.

**Packed SFT**
- Per-chat RoPE positions restart at 0.
- Attention chat plan (gqa_chat_plan_make → g_packed.chats).
- Loss: ignore 65535 (uint16 labels) + global trained-token denominator (MPI_Allreduce); backward seed W instead of 1/GRAD_ACCUM.
- Only 3 kernels change (RoPE, attention, loss), because only they mix tokens, use positions or use labels. The trainer diff is 61 lines.

**Rival libraries (code survey)**
- vLLM, TRT-LLM and SGLang: fused qk-norm+rope, forward only.
- Unsloth: fused, but no gamma gradient.
- Liger, FA Triton, TE, Quack: separate kernels, dgamma via partials + parallel reduce.
- vLLM advanced: multiple heads per warp + cp.async + PDL.

**ncu findings (Kruthik kernel)**
- fwd: 4 tokens serialized per warp.
- bwd: 1 warp/block, 128 serial tokens, 2-byte loads, 0.7 waves.
- Positions: chained wait (IMAD.WIDE pos*128 at 23% of stalls).
- Reduce: 1 block, 0.3% DRAM.
- "L2 ~70%" turned out to be a symptom; the L2 theory was refuted by v2.

**Bit-identity rules**
- Keep the per-token math, the lane mapping and the dgamma order.
- Pin the forward rotation: `__fmaf_rn(a, own, lo ? -__fmul_rn(b, partner) : +…)`.
- Same sequential sum order in the reduce.

**Model / run configuration**
- Checkpoints store weights only. The config must match (n_layers 28, rope_theta 50000; a wrong theta does not error).
- Muon SFT for a Muon-pretrained base (Moonlight Table 6), lr 5e-5.
- DCP checkpoints: 17 GB each (bf16 weights 3.4 + Muon master + momentum 12.7 + AdamW 1.4).
- Saved every 1000 steps into blumodel_step_N; prune keeps the newest 2 (`prune_old_checkpoints`).
- Auto-resume from the newest valid checkpoint (metadata.bin present).
- The 2-GPU resume is possible by design (DCP re-split, `ShardedMuon.h:315-321`; B2×W2 reads the same rows) but untested.

**Overfitting concepts (documented)**

- Epoch 1 train loss behaves like a held-out loss; epoch 2 does not.
