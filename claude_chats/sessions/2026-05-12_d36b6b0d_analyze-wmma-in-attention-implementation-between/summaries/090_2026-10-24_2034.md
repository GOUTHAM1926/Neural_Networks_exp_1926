2. Key Technical Concepts

**RoPE cp.async kernel design**
- `fused_qknorm_rope_bwd_ca_bf16_tm`: DEPTH token slots in shared memory, cp.async 16-byte loads, `cp.async.wait_group<DEPTH-1>`, per-slot `pos_next`.
- Per-token math pinned with explicit-rounding intrinsics to the original's compiled form, giving bit-identity.
- `reduce_dgamma_qk_async_bf16_tm<HD,U,STAGES>`: a shared-memory ring with cp.async; padded partial buffers (`BF16_RED_PAD_ROWS`); `cudaMemsetAsync` on the kernels' stream.

**Root cause found by decoding SASS control bits**
- The stall and write-barrier bits sit in the top 23 bits of the 128-bit instruction word.
- ptxas put all LDGs on scoreboard SB5, so every wait drained every load.
- The cp.async version uses `DEPBAR.LE SB0, 0x2` instead.

**Wave quantization**
- 72 registers → 28 one-warp blocks per SM → 32×8 B4 needs 1.39 waves.

**Trainer A/B method**
- Two `libtensor` snapshots (`libs_old` / `libs_new`) and one trainer binary without a runpath to the library, so `LD_LIBRARY_PATH` selects the arm.
- The arm is verified three ways: `cuobjdump -symbols` (not `nm -D`), `/proc/pid/maps`, and nsys kernel names.

**Power cap**
- The H200 runs at ~692 W; the backward-pass GEMMs ran 1–3% slower in the new arm.
- So the net step gain is about 60% of the kernel saving.

**Packing**
- Method A (offline, fixed rows; ours) vs method B (fixed samples per step, per-step packing).
- Rule of thumb: SFT → A; DPO → B with whole pairs; RL → B is the only option.
- Loss normalization options: per-micro-step mean, full-step mean (ours), sum loss (Tülu 3).

**Attention dispatch (latest finding)**
- GQA dispatch uses `get_arch()` → `ArchFamily::{Hopper, Blackwell_B300, Ada}`.
- `GqaChatPlan` (packed SFT, design A) is supported only on the Hopper v62 / Vj2 / Vj1d paths.

4. Errors and fixes

**RoPE pp kernel (register slots)**
- **Positions batch shuffle:** caused a MOV copy waiting on a fresh load (one stall per 32 tokens). Fixed with a per-slot `pos_next`.
- **Conditional position load:** `m < n_tok ? load : 0` caused another MOV wait. Fixed with an unconditional clamped load: `min(m, n_tok-1)`.
- **Reduce re-loads:** read-only `.nc` loads let ptxas re-load a buffer's first rows. Fixed with `__ldcg`.
- **Reduce integer overhead:** per-row clamping cost about 10 integer instructions per add. Fixed by making HD a template parameter, padding the buffers, and doing the tail test per batch.
- **`cudaMemset` on the default stream:** could race with the kernels' stream. Fixed with `cudaMemsetAsync(..., stream)`.
