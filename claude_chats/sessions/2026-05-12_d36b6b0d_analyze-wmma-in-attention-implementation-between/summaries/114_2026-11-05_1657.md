2. Key Technical Concepts:

**GPU kernels and multi-tensor launches**
- cp.async commit/wait group semantics. The commit must happen every stage, even empty (as CUTLASS `cp_async_fence` does).
- Multi-tensor kernels, two ways to pass the tensor list:
  - (A) a shared static pinned staging buffer plus async H2D. Racy, so callers sync after each launch.
  - (B) by value in the kernel launch arguments, as PyTorch `multi_tensor_apply` and TI's zero/cast/copy do. Safe, no sync.
- TI inventory:
  - zero, cast and new copy are by value.
  - scale and adam have a generic (A) version and an "sm89" (B) version; sm89 is used only when `get_arch()==Ada`, so the H200 uses (A).
  - grad_norm is generic (A) only.
  - `MultiTensorAdam_sm90.cu` has no caller (dead).

**Device queries and tensor maps**
- `cudaGetDeviceProperties` is slow per NVIDIA (~1 ms on stacks without caching). `cudaDeviceGetAttribute` takes 30–80 ns.
- On our CUDA 13 stack the runtime caches it: about 26 ns on the H200, 19 ns on the 3060.
- TMA descriptors (`cuTensorMapEncodeTiled`, about 0.144 µs) vs address replace (about 0.107 µs). CUTLASS and FA3 encode per launch.

**Measurement methods**
- nsys step-boundary analysis: optimizer phase = boundary gap − median in-step gap.
- SFT steps are detected via embedding-backward kernel groups (2 per step, Otsu split, outlier gaps dropped). The embedding forward runs about 5 times per SFT step, so it can't mark steps.
- Call-site GPU-idle attribution with `--cudabacktrace=all:1`: idle is charged to the call the CPU is inside, else the last call before it; the charges sum to the measured idle.

**Optimizer and trainer behaviour**
- ZeRO optimizers: `ShardedMuon`, `ShardedOptimizer`, `SymmetricShardedOptimizer`, all derived from `ZeroOptimizerBase`.
- Grad views are declined at world size 1, so `zero_grad` takes the per-tensor loop. At multi-GPU with `grad_view` it's one memset.
- Backward (or the gradient-norm atomics) is non-deterministic run to run. So loss comparisons are made against the same-build spread.
- Global clip: production YAML has `BLU_GLOBAL_CLIP=1`; SFT runs today used no YAML, so per-group clip.
- PyTorch `zero_grad`: `set_to_none=True` by default, otherwise `torch._foreach_zero_` (`optimizer.py:1170`).
- PyTorch `getDeviceProperties`: call_once per device. FA2 `get_compute_capability`: `cudaDeviceGetAttribute`.
