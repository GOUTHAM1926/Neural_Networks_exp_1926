2. Key Technical Concepts:

**v62 forward (`GQA_fwd_sm90.cu`):**
- Persistent kernel: 132 CTAs, 384 threads (1 TMA producer warpgroup + 2 consumer warpgroups).
- BLOCK_M=64, BLOCK_N=128, pairs of q-tiles (`decode_u` cpl/half), shared K/V pipeline.
- Ping-pong barriers need equal trip counts across the two consumers.
- Online softmax with `ex2.approx`; the mask is applied only to the diagonal tile; no −inf guard (dense never needs one).
- Dense causal waste is ~3% (diagonal tiles only).

**Vj1d backward:**
- Grid (S/64, Hq, B).
- `compute_drowsum_v22` computes D = rowsum(dO∘O_bf16).
- `fused_p_stsm` builds P = ex2(S·scale2 − LSE·log2e), applies the mask, stores bf16 P to sP.
- `fuse_dS_ldstsm` computes dS = P_bf16·(dP − D), then rounds dS to bf16.
- dQ is an fp32 TMA reduce-add (non-deterministic, ~3e-5). dK/dV are per-hq bf16 partials plus `greduce`, bit-identical run to run.
- Modes: Vj1 (`USE_FLASH=1`), v44 (`USE_DETERMINISTIC_DQ=1`).

**Design B forward (implemented):**
- Per-token `seg_start[B·T]` int32.
- `n0 = seg_start[pair*128]/128`.
- Border mask: `nt*128 < smax`, where smax = seg_start of the q-tile's last row.
- Element visible iff `seg_start(i) ≤ j ≤ i`.
- NaN guard as in Flex `common.py.jinja:115-123`: um = 0 when the max is −∞.

**Harness method:**
- References: fp64 truth, plus a PyTorch-bf16 floor (FA `attention_ref(upcast=False, reorder_ops=True)` rounding points), built per segment from tiled GEMMs that sum in index order.
- Pass rule per chat: `max|k−t| ≤ 2·max|f−t| + 2·max|(x+0.3)−0.3−x|` (FA3 / PyTorch). LSE uses the same rule (our addition).
- `--use_fast_math` in the test flags, so the references use explicit IEEE intrinsics (`__fadd_rn`, etc.), `fma`, and double exp/log.

**Library dS choices:**
- FA2 (`flash_bwd_kernel.h:591`), FA3 (`mainloop_bwd_sm90_tma_gmma_ws.hpp:893`), FA4 (`flash_bwd_sm90.py:1569`) and Flex (`flex_backwards.py.jinja:541/775`) use fp32 P.
- PyTorch mem-efficient uses bf16 P (`kernel_backward.h:341-351`, `:1959-1960`).
- cuDNN is closed source; statistically it leans fp32 P.
- All FlashAttention-style kernels compute D from bf16 O, which is the dominant shared error. PyTorch math uses a consistent row sum.

**Packing and data facts:**
- 5000 chats, 6,188,911 tokens, 1517 rows (minimum possible 1511), 1–12 chats per row, mean 3.3.
- Chat length = last label index + 1.
- TRL default packing strategy: "bfd"; TRL `shuffle_dataset` default: False.
