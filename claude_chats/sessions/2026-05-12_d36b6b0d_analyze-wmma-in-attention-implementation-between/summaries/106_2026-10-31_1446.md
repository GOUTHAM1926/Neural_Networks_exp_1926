2. Key Technical Concepts:

   **CUDA grid limits.** Grid x up to 2^31−1; y and z up to 65,535. A refused launch gives "invalid argument"; without a check it is silent.
   - Fix patterns:
     - token/sequence in grid x (vLLM, apex, TransformerEngine);
     - grid-stride loop (PyTorch CUDA_KERNEL_LOOP);
     - flattened linear grid (TE THD);
     - launch check `cudaGetLastError` (PyTorch C10_CUDA_KERNEL_LAUNCH_CHECK, c10/cuda/CUDAException.h:86; TE NVTE_CHECK_CUDA).

   **--use_fast_math.** Implies --ftz=true, --prec-div=false, --prec-sqrt=false, --fmad=true, and turns sinf/cosf/expf/logf/powf into the fast intrinsics.
   - Ours: whole libtensor and libblublas (TI Makefile:144-145, 177), since commit b66f8fc (2026-04-07).
   - Others: TE per-file list (CMakeLists:757-807); vLLM per-file; FA2/FA3 whole extension (attention only); PyTorch none.
   - Our attention uses explicit ex2.approx/rcp.approx PTX; SwiGLU uses explicit __expf. Unaffected by the flag.

   **RoPE cos/sin table.** Built once at trainer start (build_rope_cache → rope_build_cache_cuda), read by the fused QK-norm+RoPE kernel.
   - Every other training library: fp32 angle + accurate cos/sin.

   **Bug classes in our library:**
   - RoPE table builders (plain, LeRoPE) and per-token RoPE kernels (rope_kernel fp32/bf16, sm90 neox/gptj, LeRoPE alpha backward) fail at T ≥ 65,536.
   - Loss backward FALLBACK sparse_ce_backward_cuda_vec (grid_reduce{2, batch_size}) fails at rows ≥ 65,536. Training uses the safe stats path.
   - Latent: embedding (block 32×8) above 524,280 tokens per call; SwiGLU sm120 only above 262,140 rows.
   - All 21 single-block reductions loop correctly.
   - The loss SUM bug (B×T > 65,536) was fixed and pushed 10-30 (TI 6aac3bf).

   **Test methods:**
   - standalone correctness (fp64 references, bit-identity vs the old kernel);
   - microbenchmarks (CUDA events, interleaved rounds);
   - nsys per-kernel times;
   - trainer integration (step-0 val loss vs numpy reference 1.606273, step time, peak memory).
