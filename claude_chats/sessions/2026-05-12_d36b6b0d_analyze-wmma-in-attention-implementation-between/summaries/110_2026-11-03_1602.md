2. Key Technical Concepts:

   **The BluBLAS SM90 tile-map stall (old code)**
   - `sm90_tile_map_cached`: 16 slots in total, keyed by (grid_m, grid_n, hilbert), round-robin.
   - On a miss: `cudaMalloc`, then a plain `cudaMemcpy` that waits for all queued work on the legacy stream 0 (TI never calls `setCurrentStream`, DeviceCore.cpp:63; the matmul backward is single-stream), then `cudaFree` once full.
   - With trained rows, only the lm_head dX `[M_t × 512]` (tall grid M_t/128 × 2) misses every micro-batch:
     - forward `[M_t × 49280]`: not tall, square only at 98,560;
     - dW `[49280 × 512]`: fixed size.

   **Key fact behind B3/D:** a row-first table entry is i → (i/grid_n, i%grid_n), independent of grid_m. A column-first entry is (i%grid_m, i/grid_m), independent of grid_n. Hilbert needs the exact grid.

   **Fix versions**

   | version | what it is | outcome |
   | --- | --- | --- |
   | B | tall order computed in the kernel (double reciprocal) | — |
   | B2 | tall order computed in the kernel, integer divide | **rejected**: down dX +3–4%, 128k tall +0.3–0.8% |
   | B3 | host-only cache, kernel unchanged, pinned memory + `cudaMemcpyAsync` | accepted 11-02 |
   | D | shared helper `blublas_tile_order_tables.cuh` for SM90 + SM103 + SwiGLU + cluster_nn; BN=64 `_ws` split-K; sm_80/86/89 fix C | — |
   | D2 | D, but tables filled by a GPU kernel (no `cudaMallocHost`) | the version under test |
   | D3 | arena allocator to remove `cudaMalloc` | proposed, not built |

   **sm_80/86/89 tile-skip bug**
   - Formula: `sw = max(1, min(grid_y, G))`, with G = 8 for BF16 and FP16 and G = 16 for FP32 SM86.
   - Tiles are lost when grid_x > 1, grid_y > G and grid_y % G ≠ 0.
   - Fix C: the last group gets only the rows left: `g_first = (block_id/(grid_x*G))*G; sw = min(grid_y-g_first, G)`.
   - Safe already: the backward nt/tn files, and the FP32 SM89 core (used on H200).

   **Split-K**
   - The legacy BN=64 TN entry uses `Sm90Config_128x64x64` (`SPLITK_WORKSPACE = false`, so `atomicAdd`): not deterministic.
   - BN=128/192/256 already use `_ws` configs (since 2026-08-10).
   - Fix: `Sm90Config_128x64x64_ws` for even N.

   **What others do**
   - **CUTLASS:** tile order computed on the device, workspace 0. Grouped GEMM keeps sizes in device memory.
   - **DeepGEMM:** `__ldg(grouped_layout+group_idx)`.
   - **cuBLAS:** a new shape costs only CPU heuristic time; it waits only on the first use of a new kernel (`cuKernelSetAttribute` / lazy load).
   - **CCE:** valid rows only via `nonzero()` (one sync), Triton kernels, in-kernel GROUP_B with `min` for the last group, autotune off.
   - **Unsloth:** uses CCE.
   - **Liger:** cuBLAS on all rows.

   **lm-eval vs lighteval vs vLLM**
   - lm-eval is EleutherAI's harness; lighteval is Hugging Face's harness.
   - vLLM is an engine. Both harnesses can use vLLM or transformers as their backend.
   - `fmt_lm_eval.py` = lm-eval `vllm-fmt` class with the exact training ids.
