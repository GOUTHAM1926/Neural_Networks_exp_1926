2. Key Technical Concepts:

- **Global denominator.**
  - Each micro-loss = sum of answer-token losses ÷ the step's total trained tokens (all micro-steps and GPUs).
  - Backward seed = W, because ZeRO averages over GPUs. Pretraining uses seed 1/GA with a per-micro-batch N of 32,768.
  - The logged loss is a plain sum.
- **Labels and template.** 65535 = ignore. Pad id 50256. Template tulu-plain-v1 uses plain-text markers: `<|user|>\n` is 6 GPT-2 tokens and `<|assistant|>\n` is 7. No new special tokens. Vocab has 50,304 rows, of which 47 are spare.
- **F1 NaN check.** Checks the gradient norm² (`!isfinite(nsq)`) inside `step()` before the update and exits with code 4. The old loss check (`:2270`) exits with code 2.
- **Box trap.** `mpirun` on a single node passes the whole environment, so leaked `BLU_*` variables reach the run. The queue scripts unset every `BLU_*` first.
- **Epoch grouping per GPU count.** `M = N/(B·W)`. On 1 GPU, epoch 2 starts mid-step 78; on 2 or 4 GPUs it starts exactly at step 78.
- **Val rows per GPU count.** 496 rows on 1 or 2 GPUs (441,382 tokens); 480 rows on 4 GPUs (426,157 tokens).
- **`empty_cache` slowdown.** `empty_cache()` at steps 0 and 5 makes steps 1 and 6 slow. It's a colleague's leftover; he will remove it; leave it.
- **Muon scaling.** Our Muon `match_rms_adamw` scales the update to RMS 0.2 (Moonlight and GLM-4.5 do the same).
