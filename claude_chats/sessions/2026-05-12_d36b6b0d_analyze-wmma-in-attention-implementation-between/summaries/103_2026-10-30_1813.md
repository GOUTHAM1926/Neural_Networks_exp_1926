2. Key Technical Concepts:
   - **Loss-sum bug.** `sum_reduction_kernel` works in two stages.
     - Stage 1 runs ceil(N/256) blocks; stage 2 is ONE block of 256 threads; each thread loads ONE value with no loop.
     - So rows ≥ 65,536 are never added. The printed loss ≈ true × 65,536/N.
     - The denominator is counted over all N by `count_valid_targets_kernel`, which loops.
     - Gradients are unaffected: the backward uses saved max/sum and `denom`.
     - Pre-existing library code, since at least b31e831 (2026-04-10).
   - **How others sum per-token losses:**
     - PyTorch `nll_loss_forward_reduce_cuda_kernel_2d`: one block, each thread loops `for (i=threadIdx.x; i<nframe; i+=blockDim.x)`; block size `clamp(2^round(log2(N/16)),32,1024)`; no atomics.
     - `torch.sum` (Reduce.cuh): strided per-thread slices; multi-CTA partials read by the last block in index order.
     - CUB DeviceReduce: pass 1 with a capped grid and tiles in a loop; pass 2 is a single block over `ConsumeRange(0,num_items)`.
     - Liger: `torch.sum(loss_1d)`, with `loss_1d` in the input dtype (bf16).
     - FlashAttention, Quack and TransformerEngine: `loss.sum()/count`.
     - Megatron: `torch.sum(losses*loss_mask)`.
     - torchtitan: `F.cross_entropy`.
   - **Fix design: a strided loop with a 64-bit index.** It is bit-identical for N ≤ 65,536, because each thread still gets at most one value and `0.0f+x==x`.
   - **Embedding backward modes:**
     - `segmented` (Kruthik's, fp32 sums, deterministic);
     - `cooperative` (fp32);
     - `atomic` (bf16 atomicAdd, non-deterministic, ~15–93% error on frequent tokens).
   - **Context parallelism.** CP splits one row across GPUs; it is not an attention-kernel swap.
     - Ulysses can reuse our design-A kernels. KV heads must divide the CP degree: 135M → CP ≤ 2; 1.6B → CP 2, 3 or 6.
     - Ring would need new chat-aware kernels.
     - Memory scales with tokens per GPU (B×T), not T.
   - **Context length.**
     - Not stored in the weights or the optimizer state.
     - The RoPE table [T,128] is built at start from theta (`bluscript_sft.cpp:831`) and never saved.
     - RoPE settings (theta, YaRN/LongRoPE + mscale) must match the checkpoint.
     - Labs extend context in late pretraining: Llama 3 8K→128K in six stages (~800B tokens); Qwen2.5 4,096→32,768; DeepSeek-V3 4K→32K→128K with YaRN; SmolLM3 4k→32k→64k; OLMo 3 8,192→65,536.
     - Lab SFT lengths:
       - Qwen2.5 at 32,768, the same as its base;
       - Tülu 3 at 4,096 on a 128K base, i.e. shorter;
       - Llama 3: short-only SFT regressed long context; 0.1% long data fixed it;
       - SmolLM2-135M max 8,192.
   - **Packing.** Positions restart per chat, so T only decides the longest chat kept, memory and chats per step.
   - **Design-A attention (cu_seqlens style).** It skips other-chat tiles and tiles fully above the diagonal. Waste is 11.54% on stage-0 packed data: 7.48% diagonal, 3.83% chat-end, 0.23% pad.
   - **Generic attention kernels** (`gqa_v2`, `gqa_backward_dQ`, `gqa_backward_dKdV`):
     - a CAUSAL template flag plus `gen_segs {b,t0,L,0}` in `GqaChatPlan`;
     - `generic_ok = is_causal && !hopper_ok && !B300`; `BLUTRAIN_NO_SM90_GQA=1` forces them on Hopper;
     - WMMA, 1 warp per block, no cp.async.
   - **RoPE bf16 kernel.**
     - Kruthik's original (`a60099b`) already read and wrote bf16 with fp32 math.
     - We added HAS_POS (per-chat positions) and a faster backward: the `ca` (cp.async) kernel and the `pp` (register pipelined) kernel; `tm` = token-major.
     - All outputs bit-identical.
