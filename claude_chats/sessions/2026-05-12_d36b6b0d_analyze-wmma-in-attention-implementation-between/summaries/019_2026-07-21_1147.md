2. Key Technical Concepts:
   - CUDA compute capability vs CUDA toolkit version (distinct numbering schemes; common point of confusion clarified for the user).
   - `sm_XY` (plain/portable) vs `sm_XYa` (family-specific/accelerated) compile targets — same physical chip, two different instruction-set opt-in levels, not two different GPUs.
   - Hopper's `wgmma.mma_async` (warpgroup-collective, 128 threads, register-based accumulator, PTX ISA "Requires sm_90a." only) vs Blackwell's `tcgen05.mma` (TMEM-based accumulator) — proven via local PTX ISA 9.3 spec (`ptx_docs/ptx_isa_9.3.txt`) to be non-overlapping, mutually exclusive instruction families, NOT a version/superset ladder.
   - `clusterlaunchcontrol` (CLC, requires sm_100+) — also Blackwell-only, confirmed absent from Hopper.
   - Empirical arch-probe pattern: instead of a hardcoded or version-gated list (CUTLASS's approach) or never emitting "a" at all (PyTorch's approach), test-compile a trivial kernel with the candidate `"a"` flag using the actually-active nvcc, and use it only if that succeeds — ground truth for the exact toolkit on the exact box.
   - Enumerated-cap-list design (not a numeric threshold) for safe handling of unknown future architectures — "fail safe on the unknown" as the only sound design philosophy any library (including CUTLASS) can offer, since no design can pre-support an unpublished ISA.
   - Per-file GPU-family source exclusion via directory-name marker matching (`BLACKWELL_MARKERS`/`HOPPER_MARKERS`), directly modeled on BluTrain's own `Tensor-Implementations/Makefile` (`GENCODE_LEGACY`/`GENCODE_BLACKWELL`/`BLACKWELL_MARKERS`/`GENCODE_FOR`), which had already solved this identical problem.
   - Link-time symbol guards (`#ifdef BLUBLAS_HAS_SM103`) needed in ADDITION to build-time file exclusion, since a runtime-only check (`if (actual_sm_ver >= 103)`) doesn't prevent an undefined-symbol link error if the defining `.cu` file is excluded from compilation.
   - Fat binaries: multiple `-gencode` entries in ONE nvcc invocation embed multiple cubins in one `.o`/`.so`; the CUDA driver automatically selects the matching cubin at kernel-launch time — but ONLY valid when the source is truly portable across all listed targets (not possible for Blackwell/Hopper-exclusive instructions in the same unconditional source).
