2. Key Technical Concepts:

**The two varlen designs.**
- Design A = per-chat list, the cu_seqlens way. `GqaChatPlan` holds forward units `{b, t0, L, (cpl<<8)|hq}` and backward tiles `{b, t0, L, kt}`, built on the host by `gqa_chat_plan_build(plan, seg_b, seg_t0, seg_len, n_seg, B, S, Hq)`. The plan owns device memory and is freed with `gqa_chat_plan_free`.
- Design B = per-token `seg_start` (int32 `[B,T]`, the start of each token's segment). Contract: `seg_start[0]=0`, and `seg_start[t]` is `t` or `seg_start[t-1]`. Rule: query i sees key j only if `seg_start[i] ≤ j ≤ i`.
- Selection: no compiler flag. Each call picks by its arguments: nothing means dense, `seg_start` means B, a plan means A, and both together are refused.
- v62 forward has `MODE_DENSE/MODE_SEG/MODE_CHATS` (`GQA_fwd_sm90.cu:350, 364, 729, 766-773`).
- Vj1d has both modes (`GQA_bwd_vj1d_sm90.cu:428-442, 674, 760-763`).
- Vj2 has dense and B only (ported 10-15).

**Measured A vs B (10-10/10-12).**
- Forward: A 2-16% faster than B.
- Backward: A 3-5% faster on middle and long chats; B 2-4% faster only on very short chats.
- Kernel time on middle rows: forward A 501 µs vs B 538 µs; backward A 1466 µs vs B 1537 µs.
- Why: in B, boundary tiles mix two chats. In A, every chat starts its own tiles.
- Decision on 10-12: A is the default.

**What others use (verified in source).**
- FA2 `flash_attn_varlen_func(q,k,v,cu_seqlens_q,cu_seqlens_k,max_seqlen_q,max_seqlen_k)` at `flash_attn/flash_attn_interface.py:1391`.
- FA3 at `hopper/flash_attn_interface.py:890`.
- FA4 at `flash_attn/cute/interface.py:4167` (commit 94e22c9).
- TE `qkv_format="thd"` + cu_seqlens (`dot_product_attention.py:470, 550`).
- Megatron `PackedSeqParams` (`packed_seq_params.py:10-46`).
- PyTorch `varlen_attn` uses A (`varlen.py:62-65`, torch 2.14).
- Flex document mask uses B (torchtitan `attention.py:467`).
- HF: A on the FlashAttention path (`modeling_flash_attention_utils.py:480-517`), B on SDPA / eager / Flex (`masking_utils.py:734-763`).
- TRL uses A (`sft_trainer.py:1180-1202`).
- torchtitan has both (`attention.py:132, 177, 467`).
- Liger-Kernel has no attention kernel (`ops/` listing, commit 19d92e7).

**Vj2 structure.**
- Loader warpgroup plus 2 compute warpgroups.
- BM=64 query steps, BN=128 key blocks, NTHREADS=384.
- LPT block order in sections of `sw`.
- dQ via fp32 fragment-order accumulator, bulk reduce-add, then `convert_dq_frag_vj2`.
- dK/dV per-head partials stored by TMA (swizzled), then `gqa_dkdv_greduce_vj2`.

**Vj1d design-A details (to copy into Vj2).**
- Indices are segment-relative.
- Rows past L get LSE=+inf and D=0, so they contribute exact zeros.
- The segment's last key tile stores rows < L with plain stores instead of the TMA store (FA3 does the same, `hopper/epilogue_bwd.hpp:31, 263-268`).
- The plan builder (`GQA_fwd_generic.cu:422-481`) makes backward tiles per 64-key tile. Vj2 needs 128-key tiles.

**Trainer / SFT details.**
- Global trained-token denominator (unchanged by packing).
- `g_packed` global context (`PackedRows{seg_start, positions}`).
- RoPE positions = `t − seg_start`.
- Weight tying ON; loss over 50,304 rows (`vocab_size=50304`).

**Chat template.** Ours = `<|system|>\n{s}\n<|user|>\n{u}\n<|assistant|>\n{a}<|endoftext|><|user|>\n...`, with no `\n` after the end token. Tülu 3's template puts `eos+'\n'` after earlier answers and `eos` alone after the last one. Same-template rule: markers, newlines, eos 50256, generation prompt `<|assistant|>\n`, and piecewise tokenizing.

**Special tokens.**
- They bypass BPE and can be added any time; 47 spare ids (50257-50303).
- The model must learn them: mean-initialise the rows and train them in SFT.
- OLMo 3: keep them out of midtraining.
- Llama 3 base chat-token rows are zero (imone card: "The original Llama 3 8b (base) special token weights are zero, which might cause NaN gradients").
- SmolLM2 base has `<|im_start|>`/`<|im_end|>` at ids 1 and 2.
- TRL `clone_chat_template` adds tokens at SFT.
- HF `resize_token_embeddings(mean_resizing=True)` default.
