2. Key Technical Concepts:

**CPU/GPU interaction**
- CPU queues kernels on a stream; host waits happen only when the CPU reads GPU memory.
- A pageable-memory `cudaMemcpyAsync` D2H blocks the CPU.
- `cudaFree` waits for the whole GPU.

**Muon in ShardedMuon::update_one** (222 matrices = 37 layers × wq, wk, wv, wo, gate_up, down):
- weight decay → momentum → Newton-Schulz (5 iterations, bf16) → guard on U (`!isfinite(v) || fabsf(v) > 1000.0f`) → nsratio diagnostic → apply `w -= u * coef`.
- Old path: the CPU decides, with 2 waits per matrix = 444 per step, ~16 ms of CPU wait per ~142 ms step.

**GPU-side skip-flag pattern**
- PyTorch fused Adam: `found_inf_ptr`, `if (found_inf_ptr && *found_inf_ptr == 1) { return; }`.
- Apex: `noop_gmem` set on a non-finite value, never read on the host.
- Keller Jordan's Muon and torch.optim.Muon: no check at all.

**Correctness traps handled**
- `Inf*0 = NaN`, so a rejected matrix must skip the multiply entirely.
- The shared pinned metadata buffer in `multi_tensor_grad_norm_cuda` races without a sync.
- `run_sft.sh` unsets all `BLU_*` env vars, so the flag must be set in a BIN wrapper.

**F1 check (ours, 2026-09-26)**
- In `compute_norm_and_clip`: if the total grad norm is NaN/Inf, it throws `ZeroNonFiniteGradError`.
- The trainer catches it, prints `[FATAL]`, and calls `MPI_Abort`. The run stops, and no checkpoint of that step is written.

**Checkpoints**
- `BLU_CKPT_FREQ=1000`, keep 2, in `run_sft.sh`.
- `RESUME=1` continues from the newest checkpoint.

**Other findings**
- P032: `mpirun -np 1` pins rank 0 to core 0/112. Workaround: `OMPI_MCA_hwloc_base_binding_policy=none` + `taskset`.
- P032: nsys can't record call stacks because `perf_event_paranoid=4`. Workaround: my own LD_PRELOAD tracer `cudatrace.so`.
- CUDA 13 launches kernels via `__cudaLaunchKernel`, so my tracer's phase counter stayed 0.
