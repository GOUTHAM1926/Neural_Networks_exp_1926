2. Key Technical Concepts:

**Number formats:**
- fp32 has 24 significant bits; bf16 has 8 (gap 0.0078125 near 1.0).
- Half-gap rule: anything below 0.0039 added to 1.0 is lost in bf16.
- Widening bf16 → fp32 is exact.
- fp32-add-then-RN equals bf16 RN-add: 1,000,000 pairs tested, 0 differences.

**Weight tying:**
- One parameter `wte` [50304×2304], used in the lookup (a copy) and in the lm_head matmul (`h × wteᵀ`).
- The backward gives an lm_head part (all rows) and a lookup part (rows present; a sum over K repeats).
- The engine adds the 2 (`Engine.cpp:341-344`). Then the result is accumulated into the fp32 buffer (F2 `cuda_accumulate_lowp_into_fp32`).

**Embedding-backward kernels:**
- `dist_side_merge`:
  - fp32 → `embedding_backward_kernel_cooperative`: 18 blocks × 128 features, groups of 32, ballot leader, deterministic.
  - bf16 → `embedding_backward_kernel_optimized`: atomicAdd, a rounding per repeat, random order.
  - Env `BLUTRAIN_EMB_BWD_COOPERATIVE=0` makes fp32 use atomicAdd (the value is read once, static).
- BLUCCL: Kruthik's (kiruthikkanna-m) `EmbeddingBwdFused` in `dist/communication/BluCCL/kernels/fusions/embedding_fused.cu`:
  - CUB sort/RLE/scan, then `bounded_direct` (≤ 32 positions) / `bounded_chunks` (chunks of 32 into fp32 partials) / `bounded_fold` (ascending).
  - fp32 adds for both input dtypes, written once (bf16: one RN).
  - Active only in `bluscript_zero_ckpt_bluccl_fused.cpp` with `BLUCCL_FUSED_EMB=1`. The hook ignores N (`:1300`).
  - "Fused" = the file's other path, embedding bwd + reduce-scatter in one launch, which the hook does NOT use. The fused trainer = tail fusions (`BLU_FUSED_ADAMW`, `BLU_FUSED_CLIP_ADAMW`, `BLU_FUSED_MUON_PUBLISH`, the embedding hook).

**D1/D2/D3 per case** (`BLU_ALL_BF16=1`, 8 GPUs):
- fp32 table: 0 roundings to bf16.
- bf16 table:
  - D1: 1 rounding per micro-step;
  - D2: 1 rounding per micro-step;
  - the micro-step buffer is fp32 (unless `BLU_GRAD_VIEW=1`);
  - send fp32 → bf16: 1 rounding per step;
  - the switch (`multimem.ld_reduce .acc::f32 bf16x2`) returns bf16: 1 rounding per step.
- At 1 GPU, the send conversion = F4.

**Send dtype and flags:**
- `SAME_AS_PARAM` default.
- `BLU_BF16_REDUCE` / `BLU_FP32_REDUCE`. v1 refuses them. With `BLU_BF16_REDUCE`, an fp32 table still gets 2 roundings per step.

**ZeRO-1 optimizers:**
- v1 `ShardedOptimizer`, v2 `SymmetricShardedOptimizer`, Muon `ShardedMuon`.
- Muon only handles 2-D body matrices; wte and norms go to AdamW.
- #2 fix (temporaries B/B′/C/D, v1 only).
