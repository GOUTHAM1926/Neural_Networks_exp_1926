2. Key Technical Concepts:
   - SM90 warp-specialized Hopper GEMM: 1 producer + 2 consumer warpgroups (384 threads), TMA, wgmma/HGMMA, mbarriers, persistent grid-stride scheduling, thread block clusters (CGA).
   - Thread Block Cluster mechanics: `SR_CgaCtaId` (cluster rank), `barrier.cluster.arrive.aligned`/`barrier.cluster.wait.aligned` (cluster_sync), `UCGABAR_ARV`/`UCGABAR_WAIT` (SASS-level cluster barrier arrive/wait), DSMEM (distributed shared memory) cross-CTA addressing via `mapa.shared::cluster`.
   - TMA multicast: `cp.async.bulk.tensor.*.multicast::cluster` (PTX) / `UTMALDG.3D.MULTICAST` (SASS) — one leader thread issues a multicast write that replicates to all CTAs named in a `ctaMask`, each landing at the same relative smem offset and satisfying `expect_tx` at each target's full_mbar.
   - Partitioned multicast: each CTA loads only its own slice of a shared operand and multicasts that slice to all peers; combined, every peer ends up with the full operand in local smem, at 1x DRAM traffic.
   - `a_mask`/`b_mask`: 16-bit ctaMask bitmasks computed per-CTA; `a_mask` built via a loop over `n<CLUSTER_N: bit(cluster_local_m + n*CLUSTER_M)`; `b_mask` via closed form `((1<<CLUSTER_M)-1) << (cluster_local_n*CLUSTER_M)`.
   - `EMPTY_MBAR_ARRIVE_COUNT = NUM_CONSUMER_WARPGROUPS * (SHARE_M + SHARE_N - 1)`; `FULL_MBAR_ARRIVE_COUNT = 1`.
   - `release_empty` lambda: local `mbarrier_arrive` + remote `mbarrier_arrive_remote` to peers sharing a buffer (row peers for A-multicast, column peers for B-multicast).
   - The **producer tail** (§H27y.18, already fixed/validated earlier): drains outstanding empty-mbar waits before the producer warpgroup exits, preventing early CTA exit while peers still depend on it — proven correct, not the bug this session.
   - **§H14.6/§H14.7 — THE KEY FINDING THIS SESSION**: `cluster_sync()` was originally added as a **per-tile re-sync** in the persistent loop, with a code comment explicitly stating it was the "PROVEN root cause fix for the NN A-multicast crash" (bisection: crashes need large-K AND persistent together; single-tile large-K alone is safe) by bounding "leader-only multicast's cross-CTA drift" per tile. It was later REMOVED (§H14.7) on the claim "partitioned multicast is symmetric/lockstep -> race-free by construction" — a claim about data-partition symmetry that does NOT address the timing-drift mechanism H14.6 actually proved. This session restored it and proved via 50-repeat testing that this was indeed the (or a major) root cause.
   - cuBLAS kernel naming: `nvjet_sm90_tst_<A>x<B>_<Kx?>_<clusterMxclusterN>_<raster:h|v>_bz[_coopA|coopB][_splitK]_<3-letter-suffix>`. Cluster tile `AxB` = our `BM=B, BN=A` (proven earlier session, mirrored-pair grid test). The 3-letter trailing suffix (`TNN`/`TNT`/`NNN`/`NNT`) is confirmed (§H8.5, this session) to be an INTERNAL kernel-chosen detail, NOT the outer transpose mode requested by the caller.
