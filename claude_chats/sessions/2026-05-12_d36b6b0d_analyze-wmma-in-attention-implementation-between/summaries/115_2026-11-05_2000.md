2. Key Technical Concepts:

**Batched multi-tensor kernels**
- Multi-tensor kernels with the list passed by value in launch arguments: ≤48 tensors and ≤320 blocks of 128 KB per launch (copy/zero), or ≤64 matrices per launch (Muon batched).
- Alignment: unit selection U ∈ {16, 8, 4, 2, 1} from `(src^dst)&15`; the head/body/tail split computed on the absolute address; vector loops only when aligned (as PyTorch `multi_tensor_apply` and TI's `convert_type_cuda_generic` do).
- `COPY_UNROLL = 4`: 4 independent 16-byte loads before the stores, for memory-level parallelism.
- Launch checks: `cudaGetLastError` → throw, as `RoPEKernels.cu` does and like `C10_CUDA_KERNEL_LAUNCH_CHECK`.

**Where it runs and why**
- One kernel works on all architectures: plain loads and stores only, and the Makefile compiles the `_sm89` file for the machine's own `SM_ARCH`; "sm89" is a historical name.
- Flat ZeRO buffers pack tensors back to back (`offset += numel`), so slices can start unaligned.
- `getCurrentStream()` is a thread-local stream (default 0); `d2d` = `device::copy_memory` = `cudaMemcpyAsync` on the current stream and device.
- Grad views: production `grad_view: true` → `zero_grad` is one memset at W>1.
- Param views: opt-in (`BLU_PARAM_VIEW`, `cfg_.param_bucket_view`) and off in production, so the parameter scatter runs on multi-GPU too.
- PyTorch `torch.optim.Muon` is single-tensor only ("Foreach is not supported for Muon yet"). NVIDIA `emerging_optimizers`/Megatron loop per parameter. PyTorch's other optimizers default to foreach on CUDA "since it is usually significantly more performant". `clip_grad_norm_` uses `_foreach_norm` + a combine. Dion3 uses megabatching + CUDA graphs.

**Bit-identity (item 13)**
- `mul.rn.ftz.f32` for the prescale.
- The momentum expression is copied verbatim (FMUL + FFMA pattern); the weight decay is a plain FMUL.
- The batched norm keeps each tensor's own grid (`blocks_for(nchunks, kSumsqPartials=1024)`), its partials and its fold; totals are added in slot order.
- TI dropped `--use_fast_math` on 10-31 (stale comment corrected).

**Test methodology**
- Cross-checks: SASS inspection, CPU emulation of the real code (extract.sh + alignment-checked vector shims), GPU bit-identity tests, `test_muon_rsag` (RS/AG vs reduce/broadcast bit-exact at W=1 and W=2).

**Size split (latest topic)**
- The limit applies per tensor (list entry), not to the whole list.
