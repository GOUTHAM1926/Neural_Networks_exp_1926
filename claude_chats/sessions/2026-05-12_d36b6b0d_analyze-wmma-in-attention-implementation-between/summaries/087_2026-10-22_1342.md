2. Key Technical Concepts:
   - **RoPE relative-position property:** q_i·k_j after rotation depends only on i−j.
   - **Positions restart:** not mandatory with per-chat attention (it changes only bf16 rounding). It is kept for bit-exact packed==alone, training=inference, standard practice (HF DataCollatorWithFlattening, torchtitan), and ~0 cost.
   - **HAS_POS compile-time template flag:** the HAS_POS=false instantiation is SASS-identical to the old kernel (13/13 verified for fp32).
   - **Kruthik's bf16 kernel** (`fused_rms_rope_bf16`, commit a60099b on 10-01):
     - reads bf16 token-major [B,T,H*hd] and writes bf16 head-major [B,H,T,hd];
     - fp32 math inside;
     - deterministic dgamma via partials (BF16_BWD_T_CHUNKS) + reduce_dgamma_bf16_tm;
     - hd 64/128, NeoX + interleaved, no arch gate;
     - the backward saves bf16 q, k.
   - **Our SFT fp32 path:** transpose+contiguous (bf16) → widen fp32 → fused_rms_rope (fp32) → narrow bf16. It has redundant copies and keeps fp32 copies for backward.
   - **Production BLUCCL trainer** uses bf16 by default (BLU_QKROPE_FP32=0).
   - **Packed SFT data format:** inputs/labels uint16 [N,T], valid_counts, seq_lengths int32, seq_offsets int64 [N+1]; the loader refuses rows without trained tokens; only "N" and "T" are read from meta.json.
   - **GPT-2 tiktoken tokenizer must stay:** the embedding is GPT-2 ids. It is byte-level, so it encodes any language, but non-English costs 2–4x tokens.
   - **DCP weights-only init** (BLU_INIT_FROM) needs only metadata.bin + data_rank_0.bin.
   - **Same-chats reproducibility test:** build_samesteps.py, 28 rows/step worst-fit.
