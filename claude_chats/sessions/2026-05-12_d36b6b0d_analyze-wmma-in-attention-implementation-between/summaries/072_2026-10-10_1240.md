2. Key Technical Concepts:

**Our kernels (TI d96b991):**
- **v62 forward (`GQA_fwd_sm90.cu`):**
  - persistent, 132 CTAs, BLOCK_M=64, BLOCK_N=128;
  - `decode_u` pairs `cpl` with `nTiles/2-1-cpl`;
  - the producer loads `nkv = pair+1` K/V tiles from tile 0;
  - the mask is applied only on diagonal tiles;
  - the online-softmax rescale `cc0 = ex2((m0-nm0)*scale2)` has no −inf guard (`:509-512, :518`);
  - O and LSE are written with plain stores (`:605-609`).
- **Vj1d backward:**
  - grid (S/64 key tiles, hq, b);
  - `nIter = nQ - kt` (`:464`);
  - diagonal-only mask in `fused_p_stsm`; P comes from the saved LSE;
  - dQ via fp32 TMA reduce-add;
  - dK/dV are whole-64-row-tile TMA stores (`:549-555`), followed by `greduce`.
- **Design B needs:**
  - loop start at the chat tile, a border mask, and a NaN guard (forward);
  - an `nIter` bound plus the border mask (backward).
- **Design A needs:**
  - a per-chat work decode, per-chat TMA offsets, predicated stores;
  - a fix for the dK/dV whole-tile overlap: either predicated stores, or padding chats to 64 (+2.52% tokens).

**RoPE positions design:**
- A per-token int32 `[B,T]` array, like torchtitan (`rope_cache[positions]`, `rope.py:382-385`) and HF `position_ids`.
- TE and FlashAttention instead compute the position in-kernel from cu_seqlens (TE `fused_rope.cu:162-182`, FA `ops/triton/rotary.py:50-67`).
- A compile-time template flag `HAS_POS` keeps the old path bit-identical (SASS proof).

**FlashAttention test methodology (being read for Step 2):**
