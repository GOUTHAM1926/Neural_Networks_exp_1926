2. Key Technical Concepts:
   - **Bug D:** `Types.h detail::float_to_bfloat16` had `if (exponent > 0x8E)` → ±Inf. That is fp16's limit (127+15), so every finite |x| ≥ 65,536 became Inf (1,878,982,656 of 2^32 inputs).
     - The fix: remove the clamp. The RNE bias add (`lsb ? 0x8000 : 0x7FFF`, then `>>16`) handles real overflow.
     - The commented-out old version in Types.h lacks NaN handling. It turns 65,536 NaNs into Inf and 65,536 into −0/other (e.g. NaN 0x7FFFFFFF → 0x8000).
   - **Dispatch type:** `Dtype::Bfloat16` maps to `OwnTensor::bfloat16_t` (`TensorDispatch.h:49`). Templated kernels therefore use the struct's operators (`Types.h` ctor/`operator=`/`+ − * /` and compound ops), i.e. the manual `__device__ __host__` code runs on the GPU.
     - Conversion kernels explicitly use `__float2bfloat16` (`ConversionKernels.cu:148-149`), which compiles to `F2FP.BF16.F32.PACK_AB`.
   - **Real sm_90a SASS:**
     - `scalar_mul_inplace<bfloat16_t>` contained `ISETP.GT.U32.AND P0, PT, R0, 0x8e` repeated (unrolled), plus `VIADD 0x7fff/0x8000`. 688 instructions, 34 BSSY branch regions.
     - After the device intrinsic + shift patch: 192 instructions, 0 branch regions, 4 F2FP.
     - Per conversion: intrinsic = 1 instruction; manual = 17 (with a branch).
   - **CUDA 13.0 headers (checked):**
     - `__float2bfloat16_rn`: `NV_PROVIDES_SM_80` → `cvt.rn.bf16.f32`; else `__internal_float2bfloat16` (software, the host path too).
     - `__bfloat162float` → `__internal_bfloat162float`: device → `__internal_device_bfloat162float` = `NV_PROVIDES_SM_90` `cvt.f32.bf16`, else `mov.b32 %0,{0,%1}`; host = `<<16`.
     - `__float2half_rn`: `NV_IS_DEVICE` → `cvt.rn.f16.f32`; host → `__internal_float2half`.
     - `__half2float`: device `cvt.f32.f16`.
     - `__double2bfloat16`: `NV_PROVIDES_SM_90` → `cvt.rn.bf16.f64`; else an emulation that avoids double rounding.
     - `__double2half`: `cvt.rn.f16.f64`.
     - x2 variants exist: `__float22bfloat162_rn`, `__float22half2_rn`.
