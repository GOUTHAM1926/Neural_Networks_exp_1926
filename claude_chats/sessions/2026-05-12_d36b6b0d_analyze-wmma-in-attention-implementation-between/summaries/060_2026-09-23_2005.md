2. **Key Technical Concepts:**

- **Sparse cross-entropy loss**: `loss = log(Σ exp(z_j − m)) + m − z_correct` where `m = max(z)` (numerically stable log-sum-exp)
- **SFT label masking via `ignore_index`**: targets are `uint16` (0–65535), vocab 50304, so 50304–65535 is free → sentinel **65535**. PyTorch's `-100` is unrepresentable in uint16 (stores as 65436) and is silently a no-op. Default `-1` matches nothing = safe "off"
- **Bug A (3 squashes)**: intermediate loss buffers typed `T`, rounding fp32 results to bf16 three times. Forward-only
- **Bug B (vector path)**: 16-byte vector reads with element count hardcoded to 4 regardless of `sizeof(T)` — causes both misalignment (`tid*8` not `tid*16` for 2-byte types) and a type pun (8 bf16 read as 4 floats). Both forward and backward
- **`LossVec<T>`**: `WIDTH = 16/sizeof(T)` (4 fp32, 8 bf16/fp16, 2 fp64), `alignas(16)`, with `static_assert`s
- **Valid-token denominator**: PyTorch's `total_weight = batch_size − num_ignored`, emitted as a device scalar by forward, consumed by backward — no host sync
- **fp32 loss scalar**: `loss_output` and `grad_output` are fp32 by declaration, never `T`
- **Two valid designs for grad_output typing**: (1) assume-but-check = PyTorch (`check_type()` throws); (2) don't-assume = Liger/Megatron. We were doing neither
- **Anti-vacuity testing**: every masked case runs a control arm with masking off, asserting the difference equals exactly the removed loss; grad buffers poisoned with 7.0
- **Three-arm test methodology**: (A) fp64 reference, (B) dtype-T noise floor, (C) kernel; pass if `err_kernel <= 2*err_noisefloor + floor`
- **Git submodule**: BluTrain pins Tensor-Implementations at a SHA; `1c84859` and `a4c80c1` have identical tree hashes
